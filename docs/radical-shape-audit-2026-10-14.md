# “存”与扌的部件映射核查

日期：2026-10-14，Asia/Shanghai。使用 Skill：`research`。本报告记录固定来源与当前部首映射规则。

## “存”的映射来源

原始资料中的嵌套路径为：

```text
存 ⿸才子
才 ⿻扌？
```

`存` 的 `matches` 前三项都是 `[0]`，表示它们属于 `才`；`才` 的三项 `matches` 都是 `[0]`，表示它们属于 `扌`。当前构建要求常见部首只占中间部件的一部分笔画，因此这条完整三笔继承不进入“存”的可匹配部首。[S1][S2]

独立项目 AnimCJK 的固定记录为 `存⿸⿻𠂇2丨1子.3`，该记录把左上部分写作 `𠂇` 与 `丨`，支持当前扌部首排除依据。[S3]

## 原始数据证据

固定 Make Me a Hanzi dictionary 记录如下：[S1]

| 存 | `⿸才子` | `[0],[0],[0],[1],[1],[1]` | 子 | 前三笔属于才，后三笔属于子 |
| 才 | `⿻扌？` | `[0],[0],[0]` | 扌 | 三笔由同一扌形部件承担，另一个子部件未识别 |
| 扌 | `⿻二亅` | `[0],[1],[0]` | 扌 | 独立部件记录 |
| 在 | `⿸才土` | `[0],[0],[0],[1],[1],[1]` | 土 | 同样以才作为前三笔的图形部件 |

原始 `graphics` 的 medians 给出了笔画方向证据。独立“扌”三笔的起止方向分别近似为：横向、向下的竖钩、向右上方的提；独立“才”三笔分别近似为：横向、向下的竖钩、向左下方的撇。对应数据为：[S4]

## 映射算法与系统范围

构建程序 `scripts/build-data.ts` 读取 IDS 与 `matches`，按路径为直接部件收集笔画索引。`expandStrokeParts()` 递归处理嵌套部件，要求 `indices.length === record.matches.length`，并要求常见部首的索引数量小于中间部件完整笔画数量。[S2]

当前方法无法仅凭笔画数量区分“才”与“扌”这种三笔数量相同、第三笔方向不同的形近部件。Make Me a Hanzi README 说明 `matches` 是笔画到 IDS 路径的映射，也允许某些部件记录不完整；它没有承诺嵌套部件在所有字形变体中保持相同轮廓。[S1]

## 可证实的修正范围

当前完整 Make Me a Hanzi 资料中，常见部首直接映射覆盖另一汉字全部笔画的情况只有 `才→扌`：它把全部三笔标为扌，同时 `decomposition` 含未识别的 `？`。这项完整数据检查支持在嵌套传递中增加明确条件：传递的常见部首索引数量必须小于该中间部件的完整笔画数量。[S1][S2]

当前递归映射采用以下资料证据检查：

1. 直接 IDS 路径有常见部首时，继续使用原始 `matches`。
2. 常见部首传递要求其在中间部件中只占部分笔画；父部件传递的笔画数量继续要求与子部件一致。需要额外确认的形近结构通过固定 graphics 的方向和路径结构核查。
3. `才→扌` 关系在“存、在、团、材、财、茬、闭、荐、豺、鞯”中暂时排除，保留这些字符的 `才` 部件和其它已验证部件。
4. 对每个常见部首保存可回归的数据证据；无法通过证据检查的组合不进入部首条件候选，也不参与奖励部首。

回归检查覆盖全部十个同链字符，以及“密→宀”“空→宀”“打→扌”“提→扌”的有效索引。题目生成、草稿、提交、奖励和网页逐笔资料使用重新生成的同一份结果。
