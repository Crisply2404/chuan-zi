# 常见部首的笔画映射审核

日期：2026-10-15，Asia/Shanghai。使用 Skill：`research`。资料范围为项目固定的 Make Me a Hanzi dictionary、graphics 和 AnimCJK 简体中文结构记录。

## 核查资料与方法

当前 `data/dictionary.json` 中，21 种常见部首共有 3,060 个可匹配的“汉字与部首”组合。核查程序通过 `jsonlines` 读取原始 JSON Lines，通过 `parse-ids` 读取 IDS；同时检查直接部件、嵌套传递、原始笔画中心线和独立来源的部件结构。[S1][S2][S3][S4]

Make Me a Hanzi `matches` 记录汉字笔画对应的 IDS 路径。graphics 的 `medians` 与这些笔画按顺序对应，坐标纵轴向上。部件内部的笔画顺序会随着所在汉字改变；单凭笔画数量相同，无法确定笔画位置一一对应。[S1][S2]

方向比较用于寻找需要审核的资料。最终决定同时依据完整部件结构与具体中心线；方向差值本身不作为自动排除条件。生成规则应采用经过来源审核的部件关系和目标字形笔画顺序。

可重复执行的分析程序保存于 [分析程序](../.research/audit-radical-shapes-2026-10-15.mjs)，完整结果保存于 [分析结果](../.research/radical-shape-audit-2026-10-15.json)。两项中间资料由 `.gitignore` 忽略。

## 认可的部件形态

| 字符及结构 | 认可形态与笔画依据 | 常见部首规则 |
| --- | --- | --- |
| 气、复、㐌；拖右上部分 | `𠂉`，第一笔撇、第二笔横；独立亻的第二笔为竖 | 这些两笔不提供亻条件 |
| 举下方 | `⿻一十`，笔画顺序为横、横、竖 | 这些三笔不提供扌条件 |
| 奥上方 | `⿱丿冂`，顶端第一笔为撇 | 这些三笔不提供宀条件 |
| 菐中间 | `䒑`，笔画顺序为点、撇、横 | 这些三笔不提供艹条件 |
| 卉下方与奔下方 | `廾`，第二笔呈长撇形态 | 这些三笔不提供艹条件 |
| 氘内部 | `⿰丿丨`，第一笔为长撇、第二笔为竖 | 这些两笔不提供刂条件 |
| 寝中的丬 | 完整部件为丬，所在汉字的三笔顺序为竖、点、提 | 冫条件使用点和提，即零起点索引 `[4,5]` |

上述形态分别具有 AnimCJK 固定结构记录和 Make Me a Hanzi 固定中心线证据。[S1][S2][S3]

### 𠂉的两笔

AnimCJK 的固定记录包括 `气⿳𠂉一⺄`、`复⿳𠂉日夂`、`㐌⿱𠂉也`、`拖⿰扌㐌`。Make Me a Hanzi 的气第二笔中心线从 `[354,668]` 到 `[696,722]`，复第二笔从 `[387,727]` 到 `[725,781]`，均为横向右行；独立亻第二笔从 `[474,484]` 到 `[492,25]`，为竖向下行。[S2][S3]

这些结构还出现在施、汽、腹、履、覆等字内部。以认可部件关系生成嵌套映射后，亻条件涉及的当前字符为：复、气、氧、氮、氟、氯、氰、腹、覆、氨、氢、拖、施、汽、履、愎、忾、暆、氘、氛、氤、氲、氦、氪、氩、蝮、饩、馥。[S4]

### 目标字形保留笔画次序

独立丬的中心线顺序为点、提、竖。寝中的丬位于完整汉字的 `[3,4,5]` 三个笔画位置，顺序为竖、点、提。[S2]

| 寝中的笔画索引 | 起点 | 终点 | 所属笔画 |
| ---: | --- | --- | --- |
| 3 | `[297,617]` | `[314,-20]` | 竖 |
| 4 | `[176,490]` | `[262,413]` | 点 |
| 5 | `[116,158]` | `[303,316]` | 提 |

将独立丬的三个笔画转移到寝时，正确的顺序对应为 `[4,5,3]`；在这种对应中，丬的冫子部件 `[0,1]` 映射为寝的 `[4,5]`。部首条件仍然接受寝室，着色与动画使用点和提。[S1][S2][S3]

卉作为独立汉字时，下方笔画形态为廾。贲、喷、愤中的同源部件具有两根竖画，当前字形具备艹的形态。生成规则需要保留这项目标字形差异，具体笔画位置仍依据对应 graphics。[S2][S3]

## 构建规则与维护入口

审核资料应单独保存为有固定来源和笔画数量检查的 JSON 文件，构建程序在读取原始资料之后应用以下规则：

1. 直接部件使用经过审核的 IDS 字符和原始 `matches` 路径。气、复、㐌、拖的相关两笔使用𠂉；举下方使用一与十；奥上方使用丿与冂；菐中间使用䒑；氘内部使用丿与丨。
2. 嵌套传递使用明确的笔画顺序映射。寝中的丬按照 `[4,5,3]` 转移到目标汉字的位置。索引数量、唯一性、来源部件笔画数量与目标索引范围均须通过检查。
3. 最终常见部首映射按目标字形审核。卉、奔的下方只提供廾形态；贲、喷、愤继续提供真实的艹笔画。
4. 题目生成、草稿匹配、最终提交、奖励和逐笔着色读取同一份生成结果。

固定资料里的汉字数量、IDS 字符和匹配路径发生变化时，审核记录应当让构建直接报错，要求重新核查来源。项目可以继续保留原始来源文件与许可证。[S1][S2][S5]

## 影响范围与验证示例

按上述规则计算，当前记录涉及 41 个“汉字与部首”组合，共 40 个汉字；39 个汉字出现在当前有效答案中，涉及 1,635 个词语。这个数量只描述部首条件与绘制资料的范围，词语内容继续保留。[S4]

| 部首 | 当前相关字符 |
| --- | --- |
| 扌 | 举、榉 |
| 艹 | 奔、蹼、卉、幞、璞 |
| 宀 | 奥、噢、懊、澳 |
| 冫 | 寝，认可索引 `[4,5]` |
| 亻 | 复、气、氧、氮、氟、氯、氰、腹、覆、氨、氢、拖、施、汽、履、愎、忾、暆、氘、氛、氤、氲、氦、氪、氩、蝮、饩、馥 |
| 刂 | 氘 |

验证应覆盖完整资料和真实词语，至少包括以下断言：[S4][S5]

- 亻提示下，气氛、重复、拖延的相关结构不构成亻答案；拖延仍具备扌。
- 扌提示下，举例的举下方不提供扌。
- 宀提示下，奥妙的奥不提供宀；懊悔仍具备忄。
- 艹提示下，奔跑的奔不提供艹；愤怒的愤、喷泉的喷保留相应艹笔画。
- 冫提示下，寝室具备认可笔画索引 `[4,5]`；宀提示同样接受寝室。
- 氘的内部两笔只保存丿与丨的形态。
- 空穴来风的空继续保存宀，密封的密继续保存宀，冰凉的冰保存冫，提起的提保存扌。
- 整套有效字符所有 `strokeParts` 索引均为整数、范围有效、没有重复，常见部首数量小于汉字完整笔画数量。
