# 击鼓传字界面与联机规格草稿

状态：用户已确认，进入实现。日期：2026-10-09（Asia/Shanghai）。

## 本轮决定

### 2026-10-10 补充

- 开发网页使用 `/ws` 同源路径，由 Vite 将 WebSocket 升级请求代理到本机 `127.0.0.1:8787`；部署网页使用 `VITE_WS_URL` 指定独立 `wss` 服务。
- `defaultSettings` 使用 `all` 词库和两个汉字的最短答案。选择 `idioms` 词库时，界面把最短答案调整为四个汉字。
- 预设模式只展示模式入口及必要操作；详细条件、关系和参数只属于自定义模式。
- 错误提交使服务端共享截止时间立即减少一秒，输入法组合状态不会触发回车提交。
- 玩家区域保留头像、昵称、生命和中央鼓。电脑与手机的两名玩家左右排列，多名玩家围绕中央鼓排列。单人房间对面的加号头像用于添加电脑，玩家头像菜单提供房主管理操作。
- 准备和比赛页面在电脑与手机上无需页面滚动，准备、开始和输入操作位于屏幕内。
- 提示格与答案格分别居中。答案区域初始显示一个轮廓格；确认汉字后生成对应格子，并保留末尾空白格，达到房间最大长度时停止增加。新增格子播放浮现动画；服务端返回的任意连续匹配位置驱动提示格移动、重合和补全颜色，失去匹配后提示格回到原位。
- IME 组合文本、分隔符和标点保留在输入控件，不写入答案格或草稿广播。
- 全部答案格控制完整词语的原生光标，点击格子移动光标，Backspace 删除光标前面的汉字。
- 身份恢复成功后进入大厅并清空连接通知。

### 联机入口与房间访问

- 网页打开后自动连接当前部署对应的 WebSocket 服务。玩家界面不显示服务地址输入框。
- 手机或电脑从任意主机地址打开开发网页时，网页通过同源 `/ws` 使用 Vite 代理连接本机 `127.0.0.1:8787`；GitHub Pages 使用构建时提供的 `VITE_WS_URL`。
- 玩家点击“创建房间”后直接进入房间，创建动作不显示设置弹窗。
- 房间名称默认使用系统生成的房间词语，房主进入房间后可以修改房间名称、密码、是否展示、人数上限和比赛局数。
- 大厅展示设置为公开的房间，按照创建时间从新到旧排列；玩家从列表进入公开房间。
- 隐藏房间不出现在大厅，玩家通过房主复制的分享链接进入。页面不提供填写房间号、房间词或拼音来加入房间的入口。
- 分享链接使用词语拼音查询参数，例如 `?room=chou-si-bo-jian`。连续拼音也可以加入，进入后地址规范化为带连字符的拼音。全部活跃房间去除连字符后的拼音保持唯一。
- 打开分享链接后，网页自动请求进入对应房间；有密码时显示密码输入控件，验证通过后进入房间。
- 分享链接使用当前网页的完整地址生成，适配 GitHub Pages 子目录和本地开发地址。房主可以复制链接发送给朋友。
- 房间所有玩家离开后结束。连续 15 分钟没有状态变化的房间暂时从大厅隐藏，房间保留；发生加入、离开、聊天、设置或回合变化后，按照房主的展示设置重新处理大厅记录。

### 规则模式入口

规则设置页面使用五个大型模式入口，名称和顺序固定为：

1. `声母+音调`
2. `部首`
3. `字`
4. `只有音调`
5. `自定义`

前四个入口点击后立即保存对应规则到房间。模式名称表达实际提示条件。

- `声母+音调`：每轮提示一个或多个相邻位置的声母和声调，答案按照词语级普通话读音判定。
- `部首`：每轮提示部首，答案中至少一个汉字满足该部首条件。
- `字`：每轮提示一个汉字，答案必须连续包含该汉字；答案仍然需要满足当前词库和长度设置。
- `只有音调`：每轮只显示声调标记，不显示对应的拼音字母；答案按照词语级读音判定。
- `自定义`：进入单独的详细编辑页面，房主可以组合声母、韵母、声调、部首、字形部件和字词包含条件，并设置提示位置、隐藏位置、答案长度、条件关系和计时参数。

自定义页面提供三个明确操作：

- “预览提示”使用当前规则从真实词库生成示例提示，显示与局内相同的方格和字段。
- “导出规则”下载包含模式、条件、关系和参数的 JSON 文件。
- “保存规则”将当前规则写入房间设置，并返回房间设置页面。单局开始后规则锁定，单局结束后才可以再次保存修改。

预设模式和自定义模式都使用同一套服务端规则判定。房间内添加电脑玩家时，电脑使用当前房间模式和同一词库完成回答。

### 模式颜色

五个模式使用不同的水墨风格颜色。颜色用于模式入口的边线、图标、选中状态和提示标记，页面背景与正文继续使用黑白和中性灰，不使用渐变。颜色之外保留模式名称和图标，保证信息表达清楚。

- `声母+音调`：水墨朱，`#9B3D35`。
- `部首`：松烟青，`#35635F`。
- `字`：墨竹绿，`#587044`。
- `只有音调`：黛蓝，`#4C5F7A`。
- `自定义`：烟紫，`#735D73`。

### 局内界面

- 游戏区域中央显示鼓，当前回合玩家头像高亮；有效答案后下一名仍在参赛的玩家获得高亮。
- 电脑和手机的两名玩家左右排列，多名玩家围绕中央鼓排列，玩家区域保留头像、昵称与生命。
- 规则拒绝属于回合反馈：提交不符合条件、词库、长度或重复使用规则的答案时，输入格短暂抖动或变色，当前回合继续计时；页面不显示持续的规则错误文字或规则错误弹窗。
- 连接中断、协议错误和服务端故障使用独立的系统错误区域，系统错误结束后可以重新连接。
- 提示区域使用正方形汉字格。初始状态分别显示独立提示和一个居中的答案轮廓格；玩家确认汉字后按输入长度创建答案轮廓格，并保留末尾空白格，达到房间最大长度时停止增加。新增格子播放浮现动画。
- 玩家输入后，汉字逐格填入轮廓格。提示字段组成可移动的提示窗口，窗口可以附着在答案的任意连续位置；例如 `w b` 可以附着在“无往不利”的第二、第三格。
- 删除字符后如果当前输入无法匹配提示，提示窗口回到起始位置；重新形成匹配时，窗口带有短距离过渡动画并附着到新的位置。
- 每个提示格只显示当前模式开启的字段。隐藏位置显示 `∅`，声调使用带声调符号的拼音标记，不显示“一声”“四声”等文字。
- 游戏区域右上方不显示“局间准备”“等待开始”等重复阶段文字。准备按钮、开始按钮、玩家状态和比赛结果保留必要的操作信息。

## 用户故事

1. 作为网页玩家，我希望打开页面就进入连接流程，以便在电脑或手机上直接使用大厅。
2. 作为手机用户，我希望从电脑提供的网页地址打开页面后自动使用同源 WebSocket 代理，以便无需填写电脑地址或服务端口。
3. 作为 GitHub Pages 用户，我希望发布构建时指定服务地址，以便静态网页连接独立的 `WSS` 服务。
4. 作为玩家，我希望创建房间按钮直接创建房间，以便进入房间后再修改房间设置。
5. 作为房主，我希望复制一个分享链接邀请朋友，以便隐藏房间也能加入。
6. 作为玩家，我希望从大厅列表加入公开房间，以便直接选择当前可见的房间。
7. 作为房主，我希望在房间内修改名称、密码、展示状态、人数上限和比赛局数，以便创建房间后再调整细节。
8. 作为玩家，我希望看到五个表达实际玩法的模式入口，以便直接选择声母、部首、字或音调玩法。
9. 作为房主，我希望在自定义模式中预览提示、保存规则和导出规则，以便复用自己的条件组合。
10. 作为玩家，我希望答案不符合条件时只看到短暂的游戏反馈，以便继续思考并保持游戏节奏。
11. 作为参赛玩家，我希望看到中央传递物和当前玩家高亮，以便快速理解回合归属。
12. 作为手机玩家，我希望玩家区域在窄屏幕上保持清晰，以便输入法弹出时仍然能看到当前回合。
13. 作为玩家，我希望答案格保持正方形，以便输入不同长度的词语时界面稳定。
14. 作为玩家，我希望提示窗口随输入词语移动，以便看出提示对应答案中的具体位置。
15. 作为玩家，我希望空白格只表达可输入范围，不提前假定答案最短长度，以便二字、四字和七字答案都能自然输入。
16. 作为房主，我希望局间页面只保留必要按钮和玩家状态，以便画面保持清爽。
17. 作为维护者，我希望规则判定、窗口位置和最终答案使用同一套服务端逻辑，以便电脑端、手机端和未来小程序显示一致。

## 工程决定

- WebSocket 地址解析分为两个来源：构建时的 `VITE_WS_URL` 用于 GitHub Pages；未设置时使用当前网页的 `/ws` 同源路径。开发网页由 Vite 代理到 `127.0.0.1:8787`，网页不显示服务地址表单。
- 创建请求携带默认房间设置，服务端生成内部 UUID、房间词语与拼音并返回房间状态；房间元数据修改使用独立的房主命令，游戏开始后锁定会影响比赛的字段。
- 大厅只返回公开且未因 15 分钟无状态变化而隐藏的房间。隐藏房间通过拼音分享链接加入。
- 服务端生成房间词语时检查全部活跃房间的连续拼音唯一性，加入时接受带连字符和连续拼音。
- 自定义规则导出的 JSON 使用版本字段，保存模式、条件、条件关系、长度、生命和计时参数，导入校验失败时立即显示设置错误。
- 服务端草稿匹配结果返回匹配状态、窗口位置和匹配窗口对应的完整读音。最终答案由同一规则判定。
- 回合拒绝使用结构化游戏反馈消息，客户端显示短暂动画并保留输入内容或清理本次提交；系统故障使用独立的系统消息通道。
- 游戏区域使用中央鼓、玩家头像、生命、当前玩家高亮和独立回合计时。两名玩家左右排列，多名玩家围绕中央鼓排列。
- 提示显示使用固定尺寸正方形格。格子状态至少包含轮廓格、已输入格、提示格和错误反馈状态；状态变化使用 CSS 过渡。
- 由于答案长度是范围，答案轮廓格随确认的汉字数量创建，并保留末尾空白格。提交成功或切换回合后恢复一个空白格和独立提示状态。
- 删除游戏区域顶部重复阶段文字；保留可操作按钮、玩家状态和比赛结果的必要表达。
- 参考素材目录保存用户提供的 11 个图片附件、BombParty 动画和汉兜完整 SingleFile 页面。产品实现使用自有代码和自有视觉资源。

## 测试决定

- 使用真实 WebSocket 服务验证网页打开后的自动连接、同源代理、生产构建服务地址和来源校验。
- 使用真实房间验证创建按钮直接进入、默认房间名称、房间内改名、密码、公开与隐藏状态、分享链接加入、大厅排序和房主元数据修改。
- 使用真实房间验证带连字符与连续拼音定位同一房间、地址规范化、连续拼音唯一性、隐藏房间大厅展示和失效链接。
- 使用真实回合验证五个模式的提示和判定、预设模式立即保存、自定义规则预览、规则保存与 JSON 导出、无效答案短暂反馈、计时继续、当前玩家高亮和窗口位置更新。
- 使用浏览器测试验证电脑和手机左右双人布局、多人布局、页面高度、原生 IME、多字确认、格子点击、Backspace、最大长度、字符过滤、方格尺寸、提示窗口附着和删除后的返回位置。
- 使用浏览器测试确认页面不显示持续的规则拒绝横幅，也不显示“局间准备”和“等待开始”重复文字；系统连接错误仍可见。
- 使用构建检查确认 GitHub Pages 子目录、`?room=` 分享链接和 `wss` 配置正常。

## 范围之外

- 本轮不实现微信小程序页面、微信登录或小程序发布配置；继续保持与小程序共用的 WebSocket 消息格式。
- 本轮不复制汉兜的代码、颜色、图形或页面资源。
- 本轮不把用户附件作为产品静态资源发布。
- 本轮不改变 BombParty 规则研究文档中尚未核实的服务器行为。

## 验收内容

1. 隐藏房间只通过分享链接加入，页面不提供房间号、房间词或拼音加入入口。
2. 创建房间默认名称使用系统生成的房间词语，房主进入房间后修改名称和其他房间设置。
3. 规则页面使用五个大型入口，名称为“声母+音调”“部首”“字”“只有音调”“自定义”。
4. 自定义模式进入详细编辑页面，并提供“预览提示”“导出规则”“保存规则”三个操作。
5. 五个模式使用不同的水墨风格颜色，颜色只承担辅助识别作用。
6. 初始分别显示提示格和一个答案轮廓格，输入时按确认的汉字数量生成格子并保留末尾空白格，提示窗口根据服务端匹配位置移动。
7. 玩家区域显示头像、昵称、生命与中央鼓，两名玩家左右排列，多名玩家围绕中央鼓排列，准备和比赛无需页面滚动。
8. 规则拒绝采用短暂回合反馈，系统故障继续显示系统错误信息。
