# 击鼓传字

## 用户已经确定的内容

- 项目名称：击鼓传字。
- 玩法参考：JKLM.FUN 的 BombParty。
- 当前工作：按照已经讨论的要求开发网页、联机服务与数据。
- 发布形式：网页版游戏。
- 后续平台：微信小程序。
- 设备支持：电脑端和手机端分别适配。
- 房主在房间设置中选择单局游戏包含的条件；声母、韵母、声调、部首、字形部件和字词包含可以组合，并设置同字、分字或自由关系。
- 双方聊天记录持续保存，用户消息保留完整原文。
- 提示片段的形式和长度由房间选择的条件决定。
- 已确定的条件来源包括声母/拼音组合、部首/字形部件和字词包含，并增加韵母、声调与隐藏提示。
- 词语库由项目文件直接维护。
- 设备输入方式统一使用输入框，电脑端和手机端按照各自系统提供的输入法输入。
- 保留生命制度，生命归零后退出当前对局，最后仍有生命的玩家获胜；初始生命、生命上限和奖励规则由房主设置。
- 首个中文词库使用简体中文，不收录人名、地名和敏感词；繁体中文、专名和地区词库作为独立词库讨论。
- 网页端和微信小程序共享房间规则与服务端协议，允许游客加入。
- 游戏提供大厅，大厅展示多个游戏房间。
- 玩家可以从大厅加入房间，房间可以设置密码。
- 大厅房间按照创建时间从新到旧排序。
- 创建房间后直接进入房间；房间名称在房间设置中修改。
- 每个房间拥有服务端内部 UUID 和词语拼音标识；分享地址使用查询参数，例如 `?room=chou-si-bo-jian`。连续拼音也可以加入，进入后地址规范化为带连字符的拼音。全部活跃房间的连续拼音保持唯一，页面提供复制分享链接操作。
- 房间名称默认使用系统生成的房间词语，房主进入房间后可以修改名称、密码、展示状态、人数上限和比赛局数。
- 规则设置提供“声母+音调”“部首”“字”“只有音调”“自定义”五个模式入口；自定义模式进入详细编辑页面，并提供预览提示、导出规则和保存规则。
- 房间内由房主添加或移除电脑玩家，电脑使用同一套词库和条件判定完成回合；大厅不提供单独的单人测试入口。
- 声调条件可以限制某个字、部分汉字或全部汉字；也可以只显示声调作为提示。
- 部首和字形条件可以与声母、韵母、声调条件组合。
- 提示中的 `*` 表示相应汉字位置不提供限制；`sh-sh-*-x` 可以接受「生生不息」。发音字段 ∅ 表示无声母或无韵母。
- 拼音序列匹配相邻汉字，允许出现在答案任意位置；使用词语的普通话原始读音，声调变化不参与判定。
- 部首条件采用 Unihan 与 Make Me a Hanzi 的常见部件形态，对应汉字需要包含其他笔画；字形部件通过独立文件维护。
- 字词包含采用连续子串匹配，有效答案限定为词语或成语。
- 使用的数据和素材必须免费并允许商业使用，包含微信小程序用途；需要保存来源、版本与许可证。
- 大厅展示房间名称、条件、当前人数、人数上限、密码状态、游戏状态和创建者昵称。
- 单局游戏开始后加入的玩家进入观战状态，下一局开始前可以参赛。
- 提供房主转移和踢出玩家功能。
- 所有玩家离开后房间自动结束。
- 连续 15 分钟没有状态变化的房间在大厅隐藏；房间保留，出现状态变化后重新显示。
- 房间创建时可以选择是否在大厅展示。隐藏房间继续保留，只能通过房主分享的链接加入；状态发生变化后按照房主设置重新处理大厅展示。
- 房间条件只能在单局游戏开始前修改，在这一局结束前保持不变。
- 每场比赛提前设置总局数 `x`，玩家可以调整 `x`；双人比赛按多数局获胜，多人比赛按累计获胜局数最多者获胜。
- 用户提供了项目根目录的 `THUOCL_chengyu.txt`，要求核查来源与游戏适用性。
- 界面使用黑白纯色，水墨气质点到为止，保持现代简洁；参考汉兜的简洁程度，采用独立布局、配色和视觉细节。
- 声调只使用带声调符号的拼音标记，例如 `tiān`，不显示「一声」等文字。
- 组合提示按汉字位置排列，只显示已经开启的条件字段。
- Q20 已确定：聊天、准备、设置、加入、离开和回合变化更新房间活跃时间；WebSocket 心跳和倒计时刷新不更新活跃时间；断线身份保留 60 秒，主动离开立即处理。
- Q21 已确定：奖励生命从房主指定的候选随机给每人五个目标；有效答案对应的奖励条件计入个人集合，收集完成后增加一个生命并重新抽取，生命不超过上限，单局结束时重置进度。
- 回合计时：每位新玩家开始作答时重新设置，默认 10 秒；同一答案在单局内只允许使用一次，无效答案减少当前回合一秒，超时扣除一个生命。

## 2026-10-10 本轮新增决定

- 本地开发网页使用同源 WebSocket 路径 `/ws`；Vite 开发服务把该路径代理到电脑上的 `127.0.0.1:8787`。手机访问电脑网页时沿用网页来源，网页无需暴露固定 tailnet 地址。GitHub Pages 继续通过构建变量 `VITE_WS_URL` 连接独立的 `wss` 服务。
- 所有预设模式与自定义模式默认使用普通词语和成语的全部词库，答案长度下限为两个汉字。房主选择成语词库后，预设的长度下限调整为四个汉字。
- 只有自定义模式显示逐格条件、词库长度、比赛、生命和计时等详细设置。预设模式页面只显示五个模式入口和当前模式的必要操作，模式卡片文字不在卡片外重复显示。
- 回车提交的有效判定仍然遵守输入法组合状态；确认后的错误答案立即让当前共享截止时间减少一秒，并使用短暂回合反馈。
- 玩家区域保留头像、昵称、生命和中央鼓；两名玩家在电脑和手机上都左右排列，多名玩家围绕中央鼓排列。单人房间在对面显示加号头像用于添加电脑，房主通过玩家头像菜单管理玩家。

- 全部答案格控制同一个原生输入控件。点击格子移动完整词语的光标，Backspace 删除光标前面的汉字，键盘方向键沿用原生编辑行为。
- 身份过期后自动恢复大厅，恢复成功时清空连接通知。

## 2026-10-11 声调、动画与窄窗口聊天决定

### 用户已经确定的内容

- 自定义模式增加四个模板入口，分别填入“声母+音调”“部首”“字”“只有音调”的设置；填入后仍处于自定义模式，房主可以继续修改。
- 窄窗口的答案记录与聊天采用从右侧展开的页面内抽屉，保留游戏页面可见区域；抽屉内保留答案记录与聊天切换，不加入 BombParty 统计数据。
- 提示声调需要贴近字母，显示完整拼音时替换 `i` 的原点，多个字母的声母保持完整宽度。
- `zh` 等多个字母的声母保留完整宽度，声调仍在同一格中显示。声调图形使用较窄的尺寸，贴近目标元音；布局不压缩声母、韵母或其他字母。
- `i` 显示声调时使用无点字形，再把声调放在该字母上方，避免原点与声调同时出现。
- 对没有韵母的声母提示，声调使用同一格内的窄声调位置，位置靠近声母末尾，不改变声母的字母宽度。
- 方格、拼音、输入控件和提示字段使用 DOM 与 FLIP/Web Animations，保留可访问结构和稳定的输入法行为。Canvas、Pixi.js 与 Three.js 不加入方格和文字界面。

## 2026-10-12 动画验收与音效方案

### 用户已经确定的内容

- 聊天使用固定的右侧覆盖式抽屉，占据完整页面高度，聊天输入区域固定在聊天页面底部。抽屉展开后仍可以继续操作游戏，手机端适配安全区域。

### 已确认的实现

- 动画验收满足：每个格子逐个浮现；提示格向下、答案整行向上并在中间高度结合；已有字段保持原元素连续移动到目标位置；补全字段逐渐显现；失去匹配时补全字段逐渐隐藏并且提示格返回原位；运动使用先快后慢的连续曲线；文字保持自然比例。

### 音效方案

- Web Audio API 是浏览器里的播放与处理接口，适合生成点击、正确、错误、倒计时等短提示音，也可以播放项目内的音频文件。合成音色体积小，可以随游戏状态改变频率和音量，不需要保存第三方录音授权记录；合成音色难以自然模拟鼓声。
- 网上音效适合提供自然鼓声。运行时不依赖远程音频地址；选定音频后下载到项目并保存来源、作者、文件许可证和修改记录。CC0 适合未来商业使用，CC BY 需要保留署名，带有 NC 条款的素材不进入产品。
- 产品使用五个本地 CC0 录音，通过 Web Audio API 播放；换人只播放一次自然鼓声。音效提供静音开关，音量使用设备控制；游戏页面不自动播放未获用户手势许可的声音。资源与许可保存在 `public/audio/` 和 `licenses/`，构建复制完整许可。

### 原型验证结果

- 声母条件按开头匹配，s可以由sh补全；韵母条件按结尾匹配，ang可以由iang补全。无声母、无韵母继续严格要求对应字段为空。已给出的片段黑色，玩家增加的字母使用玩家颜色。
- 各人数准备房间保留电脑额外一席与可见入口。
- 大厅增加玩法教学，依次体验字、部首、声母+音调、只有音调，成功作答推进模式，最后电脑耗尽生命。教学以操作和动画引导，电脑展示多个错误尝试。普通电脑同样具有正确、错误修正与超时行为。
- 字模式成为默认并与声母+音调交换顺序：字、部首、声母+音调、只有音调、自定义。暗色模式入口的左侧条带使用各模式颜色。

## 2026-10-15 成语、字模式与教学

- 成语词库仅接受四个汉字，生成、草稿、提交和电脑采用相同范围；页面省略成语最短答案文字。
- 字模式平常提供一个汉字；进入胶着状态时保留该条件，另外随机一个位置提供声母、韵母、音调或部首之一，四种概率相同。成语使用四格，两个剩余位置为星号。
- 只提供汉字的提示格结合后保持汉字，省略补全拼音。
- 编辑光标表示原生光标位置，位于前一个汉字右侧；开头位于首字左侧，空白输入格居中。
- 教学示范初始显示提示与下方空白输入格，补全内容使用玩家颜色；箭头和头像动画说明当前与上一位玩家。
- 完成字、部首教学后，引导点击成语词库；后续声母+音调与只有音调使用四个汉字成语。
- 电脑提高正确率并展示接近提示的候选，失败过程中持续输入和尝试；教学最终让玩家获胜。

## 已确定的条件来源

### 声母/拼音组合

房间提供拼音提示，例如 `zh`、`sh-y`、`sh-yin`；玩家提交符合条件的词语。声母序列匹配相邻汉字，可以出现在答案任意位置。设置界面将声母和韵母分别列为条件，玩家不需要直接编写 `sh-yin` 语法；提示卡片只显示已经开启的字段。

自定义页面采用逐格条件：在同一格勾选的条件共同限制一个汉字，不同格的条件按连续位置排列。该规则同时适用于声母、韵母、声调、部首、字形部件和汉字。

自定义模式可以增加、删除提示格，为每格选择条件、无声母或无韵母；空格显示 *。预设模式使用固定的条件组合，模式名称直接表达提示内容。已有条件关系格式的规则文件继续支持读取。

房间可以限制某个字、部分汉字或全部汉字的声调，也可以只显示声调。`sh-sh-*-x` 中的 `*` 表示一个汉字位置不提供限制；「生生不息」符合该提示。

使用词语级的普通话原始读音；多音字接受词语文件记录的任意一套完整读音。一个答案的全部拼音条件由同一套完整读音满足。

### 部首/字形部件

房间提供部首或字形部件提示，例如 `氵`；玩家提交包含对应汉字的词语或成语。`清澈` 是用户提供的示例答案。部首条件使用实际常见部件形态，字形部件使用项目记录的结构；两者都需要真实笔画映射，匹配汉字包含其他笔画。Unihan 保存字典分类资料，Make Me a Hanzi 提供部件形态、笔画归属与字形。这些条件可以同时附加声母、韵母与声调要求，附加条件通过条件组决定是否对应同一个汉字。

### 字词包含

房间提供特定汉字或词语，例如 `天`；玩家提交包含该字或词语的词语或成语。`天翻地覆` 是用户提供的示例答案。提示采用连续子串匹配，可以出现在答案任意位置。

## 大厅与房间

大厅展示房间名称、条件、当前人数、人数上限、密码状态、游戏状态和创建者昵称，按照 `createdAt` 从新到旧排序。房间支持密码。单局游戏期间加入的玩家观战，下一局开始前可以参赛。

房主可以转移房主身份、踢出玩家。所有玩家离开后房间自动结束。房间连续 15 分钟没有状态变化时在大厅隐藏；房间内容继续保留，出现状态变化后重新显示。隐藏后仍按照创建时间排序。

加入、离开、准备、房间设置、聊天、答案提交与回合变化计为状态变化。WebSocket 心跳和客户端倒计时刷新不更新房间活跃时间。断线身份保留 60 秒，主动离开立即处理。

联机由服务端维护大厅、房间、比赛、单局游戏、计时、生命、提示和答案判定。浏览器与微信小程序通过 WebSocket 使用相同的消息格式，小程序连接 `wss` 服务。服务端广播状态变化，大厅排序与隐藏规则由服务端执行。房间密码通过加密连接传输，服务端保存密码校验值。GitHub Pages 网页连接独立服务端。

单局游戏开始时锁定条件，结束后才允许修改。比赛开始前设置总局数 `x`。双人比赛采用多数局获胜，多人比赛按累计获胜局数最多者获胜。

## 词库核查

本地 `THUOCL_chengyu.txt` 与 THUNLP 官方仓库的成语文件完全一致，共 8,519 条唯一词条。仓库采用 MIT License，README 明确允许免费用于研究和商业。发布时保存 THUNLP 的版权声明与 MIT 许可文本。

其中 7,874 条包含四个汉字，645 条包含五个至九个汉字。第二列是历史新闻文档频次 `DF`，可以作为熟悉程度的参考。文件适合作为成语候选与词频数据，正式允许提交的词条仍需筛选。它没有普通词语集合、拼音、声调或部首数据。

建议使用 THUOCL 提供成语候选和历史文档频次参考；普通词语以 CC-CEDICT 为基础，词语级读音使用 CC-CEDICT；部首形态与逐笔归属使用 Make Me a Hanzi，Unihan 提供字典分类。THUOCL 没有词语级读音和部首字段。

## 界面建议

大厅采用紧凑列表，规则页面提供模式入口和自定义编辑区域。局内页面突出玩家头像、生命、中央鼓、当前提示、剩余时间和方格输入区域；两名玩家左右排列，多名玩家围绕中央鼓排列。

采用纯白背景、黑色文字和少量中性灰。水墨气质通过标题、线条和轻量交互动效表现；游戏内容使用清晰的现代字体。布局、配色与图标采用项目自己的设计。

完整拼音直接显示常见的声调标记，如 `yīn`。只提供声母时显示 `sh`，只提供韵母时显示 `in`，只提供声调时显示带声调标记的拼音字段。声调不使用「一声」「四声」等文字。所有提示采用稳定尺寸，隐藏位置显示 `*`。

组合提示按汉字位置排列提示卡片。每张卡片只显示已经开启的条件字段：声母、韵母、声调、部首、字形部件或汉字。未开启的字段保持空白，隐藏提示位置显示 `*`。

## 条件组合与难度建议

房间通过增加、删除提示格安排条件，每格选择声母、韵母、声调、部首、字形部件或汉字，系统生成具体内容。同格条件共同限制一个汉字，空格占用一个任意汉字位置；声母或韵母可以明确要求为空。常用模式模板可以直接填入，所有条件使用同一套判定规则。

难度根据当前词库中满足全部条件、且本局尚未使用的答案数量控制。新增条件会减少或保持候选数量；增加提示信息有助于玩家想到答案。因此需要同时考虑候选数量与提示清晰程度。

生成提示时计算条件组合的交集，保证存在尚未使用的有效答案；生成与判定使用相同的词库和条件规则。`DF` 作为辅助参考，具体难度范围需要结合实际候选数量验证。
