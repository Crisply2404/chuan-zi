# 击鼓传字开发规格

状态：resolved。日期：2026-10-10（Asia/Shanghai）。验证记录见 `docs/verification.md`，界面与分享流程见 `docs/spec-draft-2026-10-09.md`。

## 使用目标

玩家在浏览器或手机上创建房间、邀请朋友，在生命与独立回合计时限制下提交符合中文条件的词语。网页部署到 GitHub Pages；联机服务另外运行，通过 WebSocket 广播房间状态。未来微信小程序共用条件判定、比赛规则和 JSON 消息协议。

## 玩家操作

1. 游客设置昵称并浏览按创建时间倒序排列的大厅。
2. 点击创建房间直接进入，默认名称使用服务端随机选择的中文词语。房主进入后修改名称、密码、人数上限、比赛局数和大厅展示状态。
   分享地址使用无声调拼音查询参数，例如 `?room=chou-si-bo-jian`。连续拼音也能加入，进入后地址规范化为带连字符的拼音。全部活跃房间去除连字符后的拼音保持唯一。
3. 从大厅列表加入公开房间，或者通过分享链接加入隐藏房间。密码房间在加入时输入密码。
4. 房主在自定义模式设置答案词库、长度、提示长度、隐藏位置数量、答案数量范围、生命和计时。
5. 条件类型包括声母、韵母、声调、部首、字形部件、连续汉字。
6. 每种条件可以关闭、随机出现或必须出现；两种条件之间可以自由、必须同字或必须分布在不同字。
7. 模式入口为“声母+音调”“部首”“字”“只有音调”“自定义”。点击前四种模式立即保存完整规则；自定义模式提供逐格条件、详细参数、提示预览、规则保存和 JSON 导出。所有模式默认使用普通词语和成语，最短答案为两个汉字；选择成语词库时长度下限调整为四个汉字。
8. 玩家准备，房主开始比赛；每局期间规则锁定。
9. 玩家依次回答，服务器使用词语级完整读音进行条件判定。
10. 无效提交立即减少当前回合计时一秒，以短暂动画反馈，保留当前回合并继续计时。同一答案在同一局只使用一次，重复提交显示短暂文字。
11. 有效提交进入下一名玩家，按照房间设置重新计时，默认 10 秒。
12. 超时扣除一个生命，重新开始计时并换人，当前题目依次顺延；场上参赛玩家全部未答出后更换题目。生命归零退出当前局，最后一人获胜。
13. 每局使用一种奖励类型，优先选择提示未使用的韵母、部首、声母；三种均用于提示时关闭奖励。每人随机获得五个目标，集齐增加一个生命并重新抽取，候选不足五个使用全部候选；生命遵守上限，每局重新收集。
14. 双人按奇数局多数胜利提前结束；多人完成规定局数，以胜局最多者获胜，并列者加赛。
15. 中途加入者观战，下一局准备后参赛；累计胜局从零开始。
16. 房主可以转移身份或移除玩家；房主离开时自动转移给仍在房间的玩家。
17. 断线保留身份 60 秒；计时继续，超时照常处理，重连恢复服务端状态。
18. 所有人离开后删除房间；连续 15 分钟无状态变化时隐藏大厅记录，状态变化后重新显示。
19. 聊天、准备、加入、离开、设置和回合变化更新活跃时间；心跳、倒计时刷新不更新。
20. 电脑和手机使用系统输入法，提交时尊重 IME composition 状态。初始显示一个居中正方形轮廓格；确认汉字后生成对应格子并播放浮现动画，保留末尾空白格，达到最大长度时停止增加。格子控制同一个原生输入控件，点击格子移动光标，Backspace 删除光标前面的汉字；组合文本保留在原生控件中，确认后的汉字进入答案格。
21. 单人房间对面的加号头像用于添加电脑；房主通过头像菜单移除电脑、转移房主或移除其他玩家。电脑使用真实词库和相同的 `WordRules` 判定完成回合，按 jieba 词频优先选择常见答案，再参考 THUOCL DF。
22. 网页自动连接联机服务。开发网页通过同源 `/ws` 代理连接本机服务；发布者构建 GitHub Pages 网页时使用 `VITE_WS_URL` 指定独立 `wss` 地址。
23. 设置范围内的全部答案使用完后，或当前设置无法产生新的有效提示时，中止本局并进入准备状态。本局不计胜局和比赛局数，已经接受的答案保留，房主可以修改规则后重新开始。

## 工程决定

- 网页使用 React、TypeScript、Vite，资源相对路径与 `?room=` 房间链接支持 GitHub Pages 子目录。
- 联机使用 Node.js 与 ws。房间、密码校验、计时、答案判定和比赛结果由服务端维护；密码使用 scrypt 保存校验信息。
- 消息使用 JSON，输入通过 Zod 验证。实现对明确的业务错误返回可读结果，内部异常立即暴露。
- 外部数据使用结构化 JSON、CSV/TSV 和 ZIP 库。CC-CEDICT 通过版本固定的 `cedict-json` 提供完整词语级读音；THUOCL 提供成语候选与 DF；Unihan 提供部首；字形部件采用允许商业使用的来源并记录许可。
- 生成提示与判定使用相同公开规则，候选数量包括本局未使用的答案。所有条件由一个匹配窗口与一套完整读音同时满足。
- 拼音显示只含被指示的部分。声调提示仅生成第一至第四声，完整轻声拼音直接显示字母，完全隐藏的位置显示 `*`，无声母或无韵母字段显示 `∅`。
- 黑白与中性灰界面，简洁现代；工具使用图标与 tooltip，条件使用分段选项与复选框，数值使用输入控件。
- 玩家区域显示头像、昵称、生命与中央鼓。头像中心按圆周等分，箭头与头像使用相同角度；两名玩家左右水平，三名玩家相差 120°，准备和比赛页面无需页面滚动。
- 提示与答案格分别居中，完整合法词语的服务端匹配位置驱动提示附着在任意连续位置。整行答案上移，提示下移，两者在中间高度结合。原有提示保持同一 DOM 元素，连续移动并保持自然比例；声调移动至对应元音上方。全部运动与补全显隐采用先快后慢的曲线。原有提示保持黑色，玩家补全部分使用其水墨颜色；独立预览使用明亮橙色 `#FFAD32`。失去合法匹配时提示返回原位，补全内容渐渐消失。
- 部首条件使用氵、扌、忄、艹、宀等实际常见部件形态，匹配的汉字需要包含其他笔画并拥有已核查的提示笔画映射；提示生成、草稿与最终答案采用同一判定。完整汉字的原提示笔画黑色，补全笔画使用玩家水墨色，字形路径按汉字从本地资源读取。
- 词语收录以日常使用范围为准，保留“人工智能、咖啡、冰淇淋”等名称。来源记录只有专业领域释义时排除，拥有日常含义时继续参与收录检查，明确保留文件保存常见的科学与健康用语。完整人工专业领域审核尚未完成。
- 房间设置提供计时方式、答案长度与生命参数。默认每个回合固定 10 秒，初始生命 3，生命上限 5，三局比赛，2 至 9 个汉字答案。
- 条件通过提示格安排，同格限制共同约束一个汉字。已有两两关系的规则文件继续支持读取；配置不可能生成有效提示时显示业务错误。
- 连续汉字条件可以覆盖提示中的相邻位置；同字和分字关系按各位置字段执行。

## 验证

测试通过规则公开接口、真实 WebSocket 和浏览器进行，使用完整真实词库；不使用 mock。

规则测试验证条件交集、隐藏位置、连续窗口、多音词完整读音、实际部首与字形部件、答案数量范围。联机测试验证大厅排序、密码、准备、规则锁定、有效与无效答案、奖励目标、超时、比赛结果、转移身份、断线与房间隐藏。浏览器验证原生 IME、多字确认、中间编辑、末尾空白格、最大长度、提示重合和返回位置、电脑与手机玩家排列、页面高度、拼音地址规范化、预设保存、连接恢复和 GitHub Pages 子目录。构建与 TypeScript 检查必须通过。

## 平台范围

本次提供可运行网页、服务端、真实数据和部署文件。微信小程序页面、微信登录以及商店发布属于后续平台工作。GitHub Pages 托管静态文件，联机上线需要公开可访问的 HTTPS/WSS 服务端地址。

## 2026-10-12 增量实现范围

1. 提示字段和答案方格使用逐字段 DOM 元素与 FLIP/Web Animations，取消文字非等比缩放；提示附着、补全显现和返回流程使用连续的先快后慢曲线。
2. 游戏页面的聊天采用右侧覆盖式抽屉，抽屉占据完整高度，输入区域固定在底部，展开期间继续保留游戏操作；手机端适配安全区域。
3. 音效使用本地许可证明确的 CC0 录音，通过 Web Audio API 播放，资源随网页构建产物发布；提供静音开关，音量使用设备控制，默认启用并在用户操作后解锁播放。换人只播放单次鼓声，每个状态变化只播放一种声音。
4. 汉字在上、拼音在下；声调线条与拼音字母接近。游戏动画采用项目定义的时长和速度曲线，系统减少动态效果设置不改变游戏动画。
5. 双指针以鼓为中心，分别指向上一位与当前玩家，鼓遮盖箭头中心；指针连续旋转，鼓的节奏随剩余时间加快。服务端广播 `previousPlayerId`，重连与切换页面后保持正确来源。

## 2026-10-13 增量要求

- 重复提交显示短暂“这个词之前输入过了”文字，并拒绝、扣除一秒；修改输入或切换回合后清除反馈。
- 部首附着进入完整汉字，黑色原提示笔画与玩家水墨颜色补全笔画采用同一 SVG 字形，保持连续移动与渐显。支持完整映射的嵌套部件。
- 当前提示记录已经超时的参赛玩家；超时依次顺延，场上参赛玩家全部未答出后更换提示。成功答案更换提示并清空记录；观战者不参与记录，离开或淘汰按剩余参赛者处理。
- 每位玩家分配稳定颜色，头像框与输入补全部分一致；全员收到草稿文本和草稿匹配，观看者保留同样的方格与动画、颜色边线，并隐藏光标。
- 接受答案广播完整提示、匹配读音与作答者颜色，头像上方短暂显示完成方格。提前提交加速完成结合，再播放返回；服务端倒计时结束时对已经收到的确认草稿判定，合法则自动提交，并执行相同动画。
- 首次部首字形请求完成后，完整笔画与字段动画全部完成才开始返回；加速持续应用于结合期间新产生的动画。返回完成后当前玩家取得输入焦点；自动提交后的同一提示与答案确认返回成功。
- 全部词语、普通词语和成语选择位于模式入口之前；切换预设保留词库。默认全部，成语最短四个字。

## 2026-10-13 大厅卡片与联机适配

- 大厅卡片响应屏幕宽度，房间名称、人数、状态、密码图标、模式标签、词库标签与条件标签保留。卡片不显示房主名称，创建顺序保持从新到旧。
- 电脑使用同一规则分步输入：等待 700ms 后，每个汉字间隔 110ms，完整答案保留 650ms 后提交。每一步广播真实草稿与匹配。
- 提交已经开始结合的答案时保持原提示 DOM 与当前动画位置；尚未开始时连续加速。当前新玩家即刻取得原生输入权限与光标，完成展示不阻止输入。
- 灰色箭头由上一名玩家指向鼓，橙色箭头由鼓指向当前玩家。两支箭头同宽；五个以内的生命在一行内显示。
- Cloudflare Workers + SQLite Durable Objects 免费方案已由用户选定；持久状态、Hibernation WebSocket 与 alarm 共用游戏规则和协议。完整词库需要经过真实内存限制验证。

## 2026-10-13 反馈、设备字体与最后同题

- 黄色箭头旋转到新玩家，上一位玩家方向的原黄色箭头沿长度翻面并变灰，尖端朝鼓；灰色箭头交接不旋转。
- 本局已经使用的词语在输入时就显示提示，位置在答案格下方。提交后拒绝仍扣一秒；其它错误以方格内部颜色与运动反馈。
- 部首附着继续使用设备字体，同一汉字文本进行区域着色。提示区域黑色、补全玩家色，用户接受连笔和交叠处的区域颜色边界。部首预设每题一个或两个，生成时等概率选择；自定义提示数量保持房间设置。
- 最后两名玩家时，前一名耗尽生命后，尚未回答同题的另一名继续作答。答对或扣除生命后仍有生命则获胜，双方零生命平局；平局计入比赛局数，双方不增加胜局。
- 词语基础数据采用 CC-CEDICT / MDBG 2026-10-12 固定快照，全部筛选继续应用。独享读音 dú xiǎng，可以回答 d-x；旋转读音 xuán zhuǎn，第二个字第四声提示不匹配。

## 2026-10-13 易误写提醒与最新提示

- 易误写表达保存在 `data/common-mistakes.json`，每项包含 `incorrect` 和 `correct`。收录由用户亲自发现并明确要求添加、输入法未识别的易误写表达。确认输入后在答案格下方显示“这个词应写作「正确词形」”，输入变化后清除。草稿与提交拒绝误写表达，错误提交仍扣除一秒；页面显示方式保持游戏可操作。
- 已接受答案完成结合后，提示格返回期间立即使用服务端当前提示，草稿与颜色同步当前作答玩家，返回的连续运动保留。
- 同一格包含部首、字形部件或指定汉字与拼音时，上方显示汉字提示，下方显示拼音提示，采用完成方格的位置、字体与声调布局；其余字段在补全后显示。
- 完成一组功能并通过测试、审查后主动创建 Conventional Commit。

## 2026-10-13 圆周方向与手机输入

- 传鼓箭头的目标方向使用 playerAngle 的圆周编号，间隔 360°/人数，两人水平、三人相差 120°。指针交接保持动画，头像尺寸和昵称布局不改变目标角度。
- 当前玩家点击答案格打开手机输入法时，答案格与当前提示位于可见区域，键盘位于答案格下方。键盘与候选栏高度变化、方向切换、连续回合保持可见和编辑权限。
- 空大厅移除空房间区域的底部分隔线，底栏分隔线保留。
- 完整轻声拼音直接显示字母，附着方格和头像正确答案使用相同方式；生成声调条件仅选择第一至第四声。
- 全部条件组合时，部首、字形部件和指定汉字完整显示在格子内，拼音保持自然比例和下方位置；320px 手机与电脑、结合和返回过程均需验证。
- 真实服务端草稿连续合法匹配两秒时自动提交；继续输入另一个合法答案或重复发送同一草稿保持原计时，失去合法匹配取消；题目或玩家更换后清除，截止时合法草稿仍自动提交。Cloudflare 的持久 alarm 与 Node 共用此行为。
- 房间准备期间各个人数均有添加电脑的入口，房间最多一名电脑。电脑拥有额外一席，maxPlayers 只计算人类玩家，最多十六名人类和一名电脑。
- contains 条件在界面显示为“汉字”，保持相邻字符匹配规则。

## 逐格自定义规则

- 自定义规则使用可增加、删除的提示格。每格选择声母、韵母、声调、部首、字形部件、汉字，具体提示由系统生成，同格全部条件限制同一个汉字。
- 声母与韵母各选择不限、提示或无声母/无韵母；无发音字段显示 ∅。整格没有条件时显示 *，该位置可以为任意汉字。
- 提示格数量独立于答案最短长度，数量可以为一至九格，且不超过最短答案长度。成语词库默认四格；至少一个格子具有条件。* 占用一个汉字位置，整段提示可以匹配答案任意相邻位置。
- 新规则保存 promptSlots，继续接受已有规则文件；全部条件按实际提示窗口判定。
- 答案最短字数与当前提示格数不相等时，答案区域显示“答案最短为 x 个字”；相等时省略。选择成语词库后的各个模式默认四格，自定义可以删除格子并保留四个汉字答案下限。
- 奖励默认开启，类型优先级为韵母、部首、声母。提示中已经使用的类型从选项中移除，全部使用时关闭奖励并显示说明；自定义可选择剩余类型。每名参赛玩家从候选中获得五个不同的目标；集齐增加一个生命，重新抽取并优先使用上一组没有出现的候选。候选不足五个时使用全部候选；候选数较小时，玩家之间的目标可以相同。
- 自定义奖励开关打开时才显示候选选择；关闭不分配目标、不增加生命。目标、收集进度和重新抽取结果随房间状态持久保存。
