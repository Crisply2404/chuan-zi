# 击鼓传字开发规格

状态：resolved。日期：2026-10-09（Asia/Shanghai）。验证记录见 `docs/verification.md`。

## 使用目标

玩家在浏览器或手机上创建房间、邀请朋友，在生命与共享计时限制下提交符合中文条件的词语。网页部署到 GitHub Pages；联机服务另外运行，通过 WebSocket 广播房间状态。未来微信小程序共用条件判定、比赛规则和 JSON 消息协议。

## 玩家操作

1. 游客设置昵称并浏览按创建时间倒序排列的大厅。
2. 创建房间并设置名称、密码、人数上限、比赛局数和大厅展示状态。
   房间名称输入框初始为空；房间公开编号由服务端从当前活跃房间未使用读音的中文词语中随机选择，并在地址查询参数 `?room=` 中使用无声调拼音。名称留空时使用中文房间编号，房主进入房间后可以修改名称，编号保持不变。
3. 从大厅加入房间，或者输入中文房间编号与无声调拼音加入隐藏房间。
4. 房主设置答案词库、长度、提示长度、隐藏位置数量、答案数量范围、生命和计时。
5. 条件类型包括声母、韵母、声调、部首、字形部件、连续汉字。
6. 每种条件可以关闭、随机出现或必须出现；两种条件之间可以自由、必须同字或必须分布在不同字。
7. 简单、困难和特色模式直接应用完整规则；自定义模式提供条件关系和详细参数，并可以导出 JSON 规则文件。提示预览只显示相应条件。
8. 玩家准备，房主开始比赛；每局期间规则锁定。
9. 玩家依次回答，服务器使用词语级完整读音进行条件判定。
10. 无效提交保留当前回合并继续计时，同一答案在同一局只使用一次。
11. 有效提交进入下一名玩家，计时低于最短时间时补到下限。
12. 超时扣除一个生命，重新开始计时并换人；生命归零退出当前局，最后一人获胜。
13. 收集指定声母集合后增加一个生命并清空集合，生命遵守上限，每局重新收集。
14. 双人按奇数局多数胜利提前结束；多人完成规定局数，以胜局最多者获胜，并列者加赛。
15. 中途加入者观战，下一局准备后参赛；累计胜局从零开始。
16. 房主可以转移身份或移除玩家；房主离开时自动转移给仍在房间的玩家。
17. 断线保留身份 60 秒；计时继续，超时照常处理，重连恢复服务端状态。
18. 所有人离开后删除房间；连续 15 分钟无状态变化时隐藏大厅记录，状态变化后重新显示。
19. 聊天、准备、加入、离开、设置和回合变化更新活跃时间；心跳、倒计时刷新不更新。
20. 电脑和手机使用系统输入法，提交时尊重 IME composition 状态。
21. 房主进入房间后可以添加或移除一名电脑玩家。电脑使用真实词库和相同的 `WordRules` 判定完成回合；大厅不提供单独的单人测试入口。
22. 玩家可以在 GitHub Pages 网页配置自己的 `wss` 联机服务地址。
23. 设置范围内的全部答案使用完后，或当前设置无法产生新的有效提示时，中止本局并进入准备状态。本局不计胜局和比赛局数，已经接受的答案保留，房主可以修改规则后重新开始。

## 工程决定

- 网页使用 React、TypeScript、Vite，资源相对路径与 `?room=` 房间链接支持 GitHub Pages 子目录。
- 联机使用 Node.js 与 ws。房间、密码校验、计时、答案判定和比赛结果由服务端维护；密码使用 scrypt 保存校验信息。
- 消息使用 JSON，输入通过 Zod 验证。实现对明确的业务错误返回可读结果，内部异常立即暴露。
- 外部数据使用结构化 JSON、CSV/TSV 和 ZIP 库。CC-CEDICT 通过版本固定的 `cedict-json` 提供完整词语级读音；THUOCL 提供成语候选与 DF；Unihan 提供部首；字形部件采用允许商业使用的来源并记录许可。
- 生成提示与判定使用相同公开规则，候选数量包括本局未使用的答案。所有条件由一个匹配窗口与一套完整读音同时满足。
- 拼音显示只含被指示的部分。仅声调显示标准声调符号，轻声以圆点符号区分，完全隐藏的位置显示 `*`。
- 黑白与中性灰界面，简洁现代；工具使用图标与 tooltip，条件使用分段选项与复选框，数值使用输入控件。
- 尚未确定的参数作为房间设置提供：计时可固定或随机，答案长度与生命均可调整。默认固定初始 20 秒，最短回合 5 秒，初始生命 3，生命上限 5，三局比赛，2 至 8 个汉字答案。
- 条件关系采用两两设置，支持交叉关系；同字关系形成位置约束，分字关系阻止对应字段出现在相同位置。配置不可能生成有效提示时显示业务错误。
- 连续汉字条件可以覆盖提示中的相邻位置；同字和分字关系按各位置字段执行。

## 验证

测试通过规则公开接口、真实 WebSocket 和浏览器进行，使用完整真实词库；不使用 mock。

规则测试验证条件交集、隐藏位置、连续窗口、多音词完整读音、实际部首与字形部件、答案数量范围。联机测试验证大厅排序、密码、准备、规则锁定、有效与无效答案、奖励声母、超时、比赛结果、转移身份、断线与房间隐藏。浏览器验证电脑和手机输入流程、提示显示、连接恢复、布局尺寸、无横向溢出和 GitHub Pages 子目录资源加载。构建与 TypeScript 检查必须通过。

## 平台范围

本次提供可运行网页、服务端、真实数据和部署文件。微信小程序页面、微信登录以及商店发布属于后续平台工作。GitHub Pages 托管静态文件，联机上线需要公开可访问的 HTTPS/WSS 服务端地址。
